# Documentation

Five things live here. Two are generated from source and three are written by hand.

|                                                             | What it is                                                                                                                                                                         |
| ----------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [`pages/`](pages/index.md)                                  | **Every page on every platform**, one file per platform. 113 routes in this repo, 152 on the platform frontend, 14 on the landing site. Generated from each repo's routing source. |
| [`components/`](components/index.md)                        | **Every exported component, hook and function**, grouped by what it is for — plus all 644 API endpoints. Generated by walking `src`.                                               |
| [`walkthroughs/`](walkthroughs/index.md)                    | **How to use the product**, written for somebody who is not an engineer. Step by step, with every on-screen label quoted verbatim.                                                 |
| [`adr/`](adr/index.md)                                      | **Why it is like this, and whether you may change it.** One decision per file, never rewritten: a changed mind is a new record. Written by hand.                                   |
| `company-setup-flow.md` · `day-one-lagos-fabric-mills.html` | Older narrative pieces on getting a company onto the product.                                                                                                                      |

## Which one you want

- **"Does this already exist?"** → `components/`. Search it before writing a new component, hook,
  helper or endpoint. This repo has paid three times over for a second copy of something that was
  already there: a second payroll engine, a second set of rating labels, a second implementation of
  a score. Each shipped because finding the first was harder than writing another.
- **"What screens are there?"** → `pages/`.
- **"How do I actually run an appraisal?"** → `walkthroughs/performance.md`.
- **"How do I decide what is waiting on me?"** → `walkthroughs/approvals.md`.
- **"Why is it like this, and may I change it?"** → `adr/`. One decision per file; read the one
  that covers a thing before you reverse it.

## Generated, not maintained

`pages/` and `components/` are derived from the code. If a route or a symbol is missing from them,
**re-derive the file rather than patching the row** — a hand-edited inventory goes stale in the way
nobody notices, which is precisely the failure they exist to prevent. How each is built is written
at the bottom of its own index.
