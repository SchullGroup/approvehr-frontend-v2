# Where things are

`docs/` holds three things. Two are generated from source; the third is written for people who do
not read code. Each folder has its own `index.md`, and `docs/index.md` says which one you want.

| | |
|---|---|
| `docs/pages/` | Every page on every platform, one file per platform. 113 routes here, 152 on `approvehr-platform-frontend`, 14 on `aprrovehr-frontend`. Generated from each repo's routing source. |
| `docs/components/` | Every exported component, hook and function, grouped by purpose — plus all 644 endpoints on `approvehr-backend`. Generated by walking `src`. |
| `docs/walkthroughs/` | The product as a user meets it, rather than as it is built. `performance.md` is a step-by-step walkthrough of the Performance module with every on-screen label quoted verbatim. |

**Search the first two before adding a component, a hook, a helper or an endpoint.** `HANDOVER.md`
records three separate incidents that were all one mistake: a second payroll engine, a second set of
rating labels, a second implementation of a score. Each shipped because finding the first one was
harder than writing another.

If a route or a symbol is missing from an inventory, **re-derive the file rather than patching the
row**. A hand-edited inventory goes stale in the way nobody notices, which is exactly the failure
those two files exist to prevent.
