# Where things are

`docs/` holds four things. Two are generated from source; the others are written by hand, one for
people who do not read code and one for the next person who is about to undo a decision. Each folder has its own `index.md`, and `docs/index.md` says which one you want.

|                      |                                                                                                                                                                                    |
| -------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `docs/pages/`        | Every page on every platform, one file per platform. 154 routes here, 152 on `approvehr-platform-frontend`, 15 on `aprrovehr-frontend`. This repo's is generated by `npm run docs`.  |
| `docs/components/`   | Every exported component, hook and function, grouped by purpose — plus all 930 endpoints on `approvehr-backend`. Generated by `npm run docs`, which walks `src`.                    |
| `docs/walkthroughs/` | The product as a user meets it, rather than as it is built. `performance.md` and `approvals.md` are step-by-step walkthroughs with every on-screen label quoted verbatim.            |
| `docs/adr/`          | Why it is like this, and whether you may change it. One decision per file, never rewritten: a changed mind is a new record that supersedes the old one. Start at `docs/adr/index.md`.   |

**Search the first two before adding a component, a hook, a helper or an endpoint.** `HANDOVER.md`
records three separate incidents that were all one mistake: a second payroll engine, a second set of
rating labels, a second implementation of a score. Each shipped because finding the first one was
harder than writing another.

If a route or a symbol is missing from an inventory, **re-derive the file with `npm run docs` rather
than patching the row**. A hand-edited inventory goes stale in the way nobody notices, which is exactly
the failure those two files exist to prevent. `npm run docs -- --check` says whether they are current.
